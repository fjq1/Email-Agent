# 指令计划与单项审核状态一致性修复

日期：2026-10-29（America/New_York）。历史阶段报告及其他功能报告保留原样。

## 问题及原因

从“审核记录”单独确认发送时，审核单与执行账本已正确完成，但父指令计划原先只在批量执行路径更新，导致最近指令仍显示“待审核处理动作”。草稿改稿后，计划详情还可能按旧预览版本查找执行结果。

## 核心实现文件

| 文件 | 职责 |
|---|---|
| [services/command_status.py](../email_agent/services/command_status.py) | 统一推导、持久化及只读展示指令状态；以审批和执行账本为准，汇总冻结的批量版本或单项当前版本 |
| [services/reviews.py](../email_agent/services/reviews.py) | 单项审核、编辑、重新处理与重试后同步所属指令计划 |
| [services/commands.py](../email_agent/services/commands.py) | 起草、分析及批量执行结束后调用同一汇总逻辑，删除独立的批量结果判断 |
| [command_views.py](../email_agent/command_views.py) | 列表与详情只读复核实际状态；未批量确认时展示实际当前版本的执行结果；完成后清除响应中的旧错误提示 |
| [templates/email_agent/command_detail.html](../email_agent/templates/email_agent/command_detail.html) | 区分冻结版本与当前审核版本，避免提示用户更新已锁定的批量批准内容 |
| [tests/test_commands.py](../tests/test_commands.py) | 在原有双平台用例补上单项发送后的状态断言，新增一项 UNKNOWN 与明确取消的针对性检查 |

## 汇总规则

- 单项确认完成后同步计划及其运行记录；Gmail 成功或 Outlook 已受理均表示这次处理完成，不额外承诺送达。
- 尚有选定邮件待分析时保留分析进度；尚有审核待决定时仍待审核；失败与 UNKNOWN 不会误报为完成。
- “不执行”属于已结束的处理决定，动作仍显示“未执行”；计划处理完成不等于全部邮件已发送。
- 用户明确取消指令时保留取消状态，不因其他单项操作覆盖其决定。
- 无批量确认时跟随审核单当前版本；有批量确认时只汇总其所选动作及被冻结版本，保留原版本校验与继续执行机制。
- GET 只修正本次响应中的展示对象，不写库、不调用模型、不触发执行。单项操作结束时持久化汇总；另有请求正在占用计划时不阻塞，展示层仍会核对账本。
